The proposed primary study asks whether the original score improves screening over validation CE or a random shortlist when every rule sees the same trained probes and has the same number of finalist slots. It compares an empirical heuristic. No benchmark result can validate the already falsified Hessian/strong-convexity claim. protocol_draft.json specifies the proposed contract; contract/shared_contract.py is a separate training-free implementation artifact being reviewed by the parent.

Keep the current CIFAR prior: inclusive integer ranges, uniform categories, log-uniform learning rate and weight decay, and valid-padding depth conditioned on kernel geometry. CIFAR currently uses one convolution per block. Save one explicit proposal manifest per dataset/search block before training, including duplicate occurrence IDs. All rules consume exactly that manifest. Candidate/phase seeds exclude method names, score ranks, worker order and completion order. The shared subset and shuffle streams are prospective pairing controls, not a claim of replaying the older candidate-specific RNG path.

Each candidate receives one constant-LR epoch on the same ordered 1,500-example subset of the 40,000 fit rows. Original RMS and validation CE are measured from that same saved probe. The recommended common pool requires a finite positive returned RMS score and finite nonnegative CE, with no 0.1 threshold. This conditions every control on score computability: an all-zero activation case whose original function returns infinity remains excluded for every rule and visible in the ledger. It is not a study of whether rejecting such models helps. No failed/rejected probe is replaced, and fewer than K common candidates fails the paired block.

This fixed-attempt ablation changes current STCVX's 100-eligible/10-finalist/1,000-attempt policy. The author must approve that distinction before publication. A separately approved legacy-threshold sensitivity can make all three rules rank the same first 100 probes with q>0.1, charging all rejected attempts. Those controls are then proxy-threshold conditioned. Filtering only the original arm instead compares complete policies with different candidate populations and costs. Neither design should be silently renamed as the other.

Finalists start fresh, train up to 100 epochs with the same cosine horizon and installed Keras EarlyStopping on actual validation CE (patience 25, restore best weights). The search selects its candidate by restored-checkpoint validation accuracy, breaking ties by stable candidate ID. Thus checkpoint CE, candidate accuracy, and eventual test error are three distinct quantities. Fit/validation rows are [0:40000] and [40000:50000] of official training order. Official tests remain outside all search APIs and are evaluated only after suite selections are sealed. Historical CIFAR test exposure still limits claims that these datasets were untouched.

The smallest proposed development panel is eight probe attempts, two finalist slots per rule, one paired block for each of CIFAR-10 and CIFAR-100, with the full split and stopping lifecycle. It uses no official tests and supports integration/cost checks only. The separate publication proposal is 100 attempts, ten slots, and 20 paired search randomizations per dataset; these counts require author and resource approval. They do not imply that the remaining paid-compute budget can cover the suite. Ranges, seeds, thresholds and repetition counts are not selected by examining favorable pilot outcomes.

Train the union of shortlists once with shared candidate/phase identity, preserving every restored checkpoint. Charge each selected fit fully to each relevant arm's logical cost, while recording actual shared execution once. Equal counts do not equal compute: architectures and early stopping change work. Charge all probes, inference, rejected attempts, failures, optimizer overhead and I/O. A random-shortlist policy would ordinarily skip probes, so these controlled-ablation timings cannot establish a deployment speed advantage. Shortlist-union outcomes also cannot identify full-pool correlations, pool-best regret or an oracle.

For publication, report test-error differences paired by search block, separately by dataset, alongside CE, completion rates and actual work. Retain every assigned block. Missing results require explicit failure reporting and bounded paired effects, not favorable complete-case headline comparisons. Checkpoint reloads and an independent ledger/statistical audit precede final interpretation.
