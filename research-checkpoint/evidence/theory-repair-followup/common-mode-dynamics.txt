Common-output shifts: implementation, training dynamics, and practical scope

This note separates an algebraic invariance check from evidence about ordinary training. It does not infer practical HPO failure from the size of an artificial shift. Main manuscript and prior experiment artifacts are unchanged.

The executed normalization panel used the Keras output kernel W with shape D by K, hidden activations h, and output bias b. In normalization-audit/check_saved_models.py:71-76, the scalar cases construct Head(hidden, weights + shift, bias). The protocol's scalar shifts are -100, -1, 0, 1, and 100. Another case adds linspace(-2,2,D) to every class column. These are algebraic transformations of saved head arrays; they do not run additional training or overwrite the original model checkpoint. The bias is unchanged in every case.

For a row vector v, W' = W + v 1^T gives z'(x) = h(x) W + b + (h(x) v) 1^T. It therefore adds the same scalar to all class logits for each input; that scalar can differ between inputs. Softmax probabilities and predicted labels are identical on every possible input in exact arithmetic, not only the sampled inputs. The numerical panel checks finite-precision errors separately. A scalar kernel shift c is the special case v = c 1_D, giving a common logit shift c sum_j h_j(x).

This transformation leaves the score's probability and hidden-activation factors unchanged and changes the kernel denominator. In the image implementation the denominator is RMS(W), equal to ||W||_F/sqrt(D K); the same effect applies to the unnormalized Frobenius denominator at fixed shape. An output-bias-only shift b' = b+c1 would also preserve probabilities, but would not change this kernel-only denominator. That was not the executed experiment.

Write W_g = rowmean(W) 1^T and W_c = W-W_g. The decomposition is orthogonal in Frobenius inner product, so ||W||_F^2 = ||W_c||_F^2+||W_g||_F^2. Class-centering removes W_g and is the minimum-norm kernel in this prediction-equivalent family. If e = ||W_g||_F^2/||W||_F^2, centering changes an otherwise identical ratio score by exactly 1/sqrt(1-e). Thus e=0.10 would change it by about 5.4%, not by hundreds of times. This is an illustrative identity, not a measured checkpoint statistic. The practical-gauge-followup analysis measures e and ranking changes from actual saved candidates.

The user's practical objection is consequential: constructing a very large v establishes that the score is not function-invariant, but does not show that the training protocol produces such variation or that the variation changes HPO decisions. The stationary, already-centered counterexample in theory-assumptions-review is a separate test of the claimed universal Hessian lower bound. Neither its validity nor its failure depends on an extreme gauge shift.

For unregularized mean cross-entropy and a standard affine softmax head, the per-example kernel gradient is h^T(p-y). Since sum_k(p_k-y_k)=0, every row's gradient sums to zero. Ordinary scalar-step SGD consequently preserves the common-mode kernel component in exact arithmetic, even while earlier features change. Momentum initialized at zero preserves this property. Scalar decoupled weight decay multiplies the existing common mode by its shrinkage factor; it does not create a new one. These statements assume this objective/update rule, no class-dependent preconditioning or regularizer, and exact arithmetic.

The pilots instead use Adam with weight decay. The installed Keras implementation applies the update alpha*m/(sqrt(v)+epsilon) coordinatewise, so a zero class-sum raw gradient does not imply a zero class-sum update. The common mode may therefore drift. This is a possible mechanism, not evidence that the drift is large in these runs. The installed source is <ORIGINAL_CHECKOUT>/.venv/lib/python3.12/site-packages/keras/src/optimizers/adam.py:119-141; scalar decoupled decay is in base_optimizer.py:960-967. The frozen lifecycle model source selects Adam at lifecycle-pilot/run-prepared-20261002-v1/sources/image/src/util.py in get_mnist_model. Adam's original algorithm is Kingma and Ba, https://arxiv.org/abs/1412.6980, Algorithm 1. The common-mode consequence here is our direct algebraic deduction from that update.

Random initialization also need not start in the centered gauge. For independent zero-mean entries with variance s^2, E||W_g||_F^2 = D s^2 and E||W_c||_F^2 = D(K-1)s^2. The ratio of expected common-mode energy to expected total energy is 1/K. This expectation calculation does not substitute for observed initialization/checkpoint statistics, nor does it claim an exact ratio in a realized model.

Centering removes this particular nuisance; it does not establish a Hessian bound, remove adjacent-layer rescaling, or guarantee improved classification ranking. The narrow practical question is whether naturally occurring common-mode variation affects rankings and selected endpoint task metrics under the actual fixed training protocol. The current reanalysis uses existing development checkpoints and reused validation rows, so any answer remains exploratory.
