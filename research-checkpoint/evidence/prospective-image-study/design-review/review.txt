The proposed CIFAR-10/CIFAR-100 comparison is coherent as a prospective screening-score study. It preserves the original RMS rule as one arm and compares the exact head trace, early tuning CE, and random selection on the same eight frozen candidate attempts. Each arm receives two final-training slots. The seven-dimensional prior remains the previously reviewed repository prior; no range, score direction, threshold, seed or architecture restriction is selected from KMNIST outcomes. The spent KMNIST holdout remains outside this study.

The recommended size is four paired blocks per task if the outcome-blind timing and memory gate passes, otherwise the predeclared first two blocks per task. Both tasks use the same repetition prefix from IDs 2000..2003. The four-block maximum is 64 probes and 64 distinct final fits, 6,464 epochs and 4,001,536 optimizer updates. The two-block maximum is 32 probes and 32 final fits, 3,232 epochs and 2,000,768 updates. These are conservative maxima with no shortlist-overlap or early-stopping savings assumed. Neither size is the deferred 20-block publication benchmark.

The common eligible pool requires completed probes, finite positive original RMS, finite nonnegative trace and finite nonnegative tuning CE. Trace zero is allowed. The strict original-score >0.1 flag is logged but not applied; its effect is not estimated by this comparison. All candidates and rejected attempts remain in the cost ledger. This is an ablation of ranking in a common computable pool, not the production procedure that collects 100 threshold-eligible probes and selects ten.

Every finalist starts fresh with candidate-and-phase-based seeds, the full 40,000-row fit split, batch size 64, a 100-epoch cosine horizon and validation-CE early stopping with patience 25. The restored checkpoint minimizes monitored tuning CE. Candidate selection maximizes the restored checkpoint's tuning classification accuracy, with candidate ID alone breaking ties, preserving the CIFAR runner. This is explicitly different from the earlier KMNIST CE tie breaker. Classification error on the official test is primary; loss is not a substitute endpoint. Any incomplete selected final blocks complete-study test finalization, and all task-block decisions must be sealed before test inference. Union reuse saves physical work while each arm retains its own logical training charge.

The trace has a valid interpretation only in the declared head-kernel coordinates with features and bias fixed. Fixed per-coordinate local noise is the convention. Because the prior varies hidden width and learned feature scales, total perturbation energy and raw trace can change with representation. For h -> c*h and W -> W/c, predictions stay fixed while trace scales by c**2. The protocol records this limitation and does not normalize away an unfavorable result after inspection. Raw traces are not pooled across the 10-class and 100-class tasks, and no full-network flatness or future-accuracy guarantee is asserted.

Historical CIFAR code used official-test scores during HPO, so these benchmarks cannot be described as globally untouched. Sealing the official tests against this study's calibration, fitting, stopping and selection gives prospective within-study separation and should be described that way. Reserving formerly used training rows does not erase their history. CIFAR-10.1 is excluded from this launch. A future separate protocol could use its publisher-recommended v6 collection as an external CIFAR-10 check, with its own project-use and image-data license audit. It is a different collection, not an interchangeable repair of the historical official-test estimate. The publisher describes its versions and their large overlap at https://github.com/modestyachts/CIFAR-10.1; the distribution-shift interpretation is discussed at https://arxiv.org/abs/1806.00451.

Independent static verification reproduced all eight candidate manifests, all 64 decoded configurations, and all 552 parent/augmentation-child seeds without a collision. It also reproduced the convolution/dense MAC counts, trainable and BatchNorm nontrainable parameter counts, and the 5.872499205 GiB estimate for saving both phase checkpoints for all candidates. That storage figure excludes file metadata, scalar optimizer/RNG state, temporary files and calibration artifacts. The immutable source plan remains unchanged.

Minimum/median/maximum MAC representatives do not establish runtime or peak-memory bounds. The separate calibration-coverage.json adds three static extreme cases to the initial six: CIFAR10/2000/c000003 for largest single convolution output, CIFAR100/2002/c000004 for parameter count, and CIFAR100/2003/c000002 for largest single convolution output. CIFAR-10's largest-parameter case was already represented. Nine cases improve coverage; the final timing plan must still explain conservative extrapolation to every frozen candidate.

Actual backend work matters to that forecast. Every epoch currently computes separate inference over the full fit split and full tuning split, in addition to training. It also performs a post-phase tuning pass, and probes compute scores on all 1,500 probe examples. The design includes these existing costs. The current history already retains train/tuning CE and accuracy, callback decisions, steps, learning rate, shuffles and augmentation state; phase metadata include parameter count. No new bookkeeping or all-model reload is promised. Only selected checkpoints are loaded by the separately costed finalizer.

The current conservative ledger is $2 reserved for two failed L4 recovery attempts, $1 for calibration, $42 for scientific training/search, and $5 for storage, network, finalization, verification and contingency, totaling the authorized $50. No throughput estimate is available: both L4 attempts failed regional capacity and no calibration ran. The current quoted Netherlands g2-standard-4 compute rate is $0.742916046/hour, with other charges still requiring a complete quote. The draft therefore separates a design freeze from an executable launch freeze. Final hardware, profiling steps, dataset/source hashes, alert access, storage retention, runtime caps and the measured outcome-blind cost gate must be completed before scientific launch. This is an execution blocker, not a need to ask the author to resolve routine scientific defaults.

Read-only implementation review found no new mathematical or selection defect in the three-file four-arm extension. The strict complete-suite finalizer remains a separate integration review. Read-only review of prepare_cifar.py confirmed that the pinned archive hash is checked before pickle decoding, only training/class-metadata members are decoded, CHW bytes are converted correctly to float32 NHWC, fixed normalization and the 40k/10k split are retained, and existing output directories are refused. No production source, candidate plan, existing evidence or manuscript was edited in this design review. No model or dataset-array work was performed.
